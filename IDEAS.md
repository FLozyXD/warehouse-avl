**Создать систему для отслеживания наличия товаров на складе с функциями учета и контроля запасов.**
1. Полная реализация выбранной структуры данных с соблюдением всех её свойств. Обоснование выбора структуры данных и подтверждение ее эффективности.
2. Консольный интерфейс для взаимодействия с системой.
3. Возможность сохранения и загрузки данных из файла.
4. Тесты для проверки работоспособности.
- **Каждый товар содержит: ID, название, категорию, количество, цену, мин. допустимое количество.**
- **Операции: добавление, удаление, обновление количества, поиск товаров.**
- **Поиск по названию, категории или диапазону цен.**
- **Функция формирования отчетов о наличии товаров.**
==Файл храним в формате .csv==

**Основная часть структуры**
Есть основная ==хеш таблица ==в ней мы храним всё кроме **категории** и **цены**
- В хешфункцию мы вводим **имя**
- В поле значений храниться имя, id, количество, минимальное количество
- Есть поля со ссылками на **категорию в части категорий** и на **цены в части цен**
- **Поиск по имени**: 
	- Находим через хеш ячейку с нужным *именем*
		- Если нет выводим отсутствие 
	- Проходим по ссылке на категории и на цену 
		- Запоминаем 
	- Выводим результат
- **Удаление и изменение количества** происходит аналогично поиску с затиранием ссылок

**Часть категорий**
Так же есть ==хеш таблица== с категорией
- В хешфункцию мы вводим категорию
- В поле значений мы храним категорию
- Есть ссылка на **имена в основной части**
- **Поиск по категории:** 
	- Находим через хеш ячейку с нужной *категорией* 
		- Если нет выводим отсутствие 
	- Проходим по всем ссылкам и получаем все продукты а из них и цены 
		- Запоминаем 
	- Выводим

**Часть цен**
Цены мы храним как ==отсортированный список==
- Хранит цены
- Есть ссылка на **имена в основной части**
- **Поиск по цене** 
	- Бинарным поиском находим необходимую цену
		- Если нет выводим отсутствие 
	- Проходим по всем ссылкам и получаем все продукты а из них и категории 
		- Запоминаем 
	- Выводим
